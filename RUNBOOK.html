Runbook

Arrancar o BikeShop

Escolha onde quer correr a loja. Os passos mudam conforme a escolha.

Docker

A infraestrutura e os 6 serviços correm em containers. Só é preciso o Docker Desktop e o Java 17 (para compilar).

  1. Abrir o Docker Desktop

    Esperar até aparecer Engine running no canto inferior esquerdo.

  2. Abrir o terminal do Docker

    No Docker Desktop, carregar em >_ Terminal, no canto inferior direito. Abre um terminal já ligado ao Docker.

  3. Ir para a pasta do projeto

    cd C:\ESTG\BikeShop

  4. Arrancar

    Liga a infraestrutura, compila os JAR se faltarem, constrói as imagens e espera que os serviços respondam (1 a 3 minutos).

    powershell -ExecutionPolicy Bypass -File scripts\arrancar.ps1
    BikeShop pronto: http://localhost:9080/
    Depois de mudar o código, acrescente -Compilar no fim, para recompilar e reconstruir as imagens.

  5. Abrir a interface

    A loja, a arquitetura com o estado de cada serviço e o menu Ferramentas (Eureka, RabbitMQ, Adminer, Jaeger, Swagger UI). Os containers aparecem no Docker Desktop, em Containers, nos grupos bikeshop-infra e bikeshop-apps.

    start http://localhost:9080/

  6. Testar a SAGA do princípio ao fim

    Encomenda paga, pagamento recusado com compensação e encomenda sem stock.

    powershell -ExecutionPolicy Bypass -File scripts\e2e-test.ps1
    Todas as verificacoes OK

  7. Parar

    Para os serviços e a infraestrutura. Os dados ficam guardados; com -ApagarDados no fim voltam os dados de exemplo.

    powershell -ExecutionPolicy Bypass -File scripts\parar.ps1

VS Code

Para programar: a infraestrutura fica em Docker e os 6 serviços correm no VS Code, com breakpoints.

  1. Abrir o Docker Desktop

    Esperar por Engine running. As bases de dados e o RabbitMQ correm lá.

  2. Instalar a extensão Java

    Em Extensions (Ctrl+Shift+X), instalar o Extension Pack for Java (Microsoft). Só na primeira vez.

  3. Abrir a pasta do projeto

    File › Open Folder e escolher C:\ESTG\BikeShop.

  4. Arrancar a infraestrutura

    No terminal do VS Code (Ctrl+`): 4 PostgreSQL, RabbitMQ, Jaeger e Adminer.

    docker compose up -d --wait
    Container bikeshop-rabbitmq Healthy
    Se os serviços estiverem a correr em Docker, pare-os primeiro, porque usam as mesmas portas: docker compose -f docker-compose.apps.yml down

  5. Esperar por "Java: Ready"

    Na barra de baixo. Na primeira vez demora, porque importa os 6 módulos Maven.

  6. Correr "BikeShop (todos)"

    Abrir Run and Debug (Ctrl+Shift+D), escolher BikeShop (todos) na lista de cima e carregar em ▶. Arranca o registo e os outros 5; cada um fica com a sua consola.

    Para correr só um, escolha-o na mesma lista (bikeshop-catalogo, …). O bikeshop-registo tem de estar sempre a correr.

  7. Confirmar

    Esperar uns 30 segundos, para os serviços se registarem no Eureka, e no terminal:

    .\scripts\e2e-test.ps1
    Todas as verificacoes OK

  8. Parar

    Botão ■ na barra de debug (Shift+F5) para os serviços; depois a infraestrutura:

    docker compose down

IntelliJ IDEA

Para programar: a infraestrutura fica em Docker e os 6 serviços correm no IntelliJ, com breakpoints.

  1. Abrir o Docker Desktop

    Esperar por Engine running. As bases de dados e o RabbitMQ correm lá.

  2. Abrir o projeto

    File › Open, escolher o pom.xml da raiz (C:\ESTG\BikeShop\pom.xml) e Open as Project.

  3. Esperar pelo Maven

    Até a barra de baixo deixar de indexar e aparecerem os 6 módulos bikeshop-*.

  4. Arrancar a infraestrutura

    No terminal do IntelliJ (Alt+F12): 4 PostgreSQL, RabbitMQ, Jaeger e Adminer.

    docker compose up -d --wait
    Container bikeshop-rabbitmq Healthy
    Se os serviços estiverem a correr em Docker, pare-os primeiro, porque usam as mesmas portas: docker compose -f docker-compose.apps.yml down

  5. Correr "BikeShop (todos)"

    Na lista de configurações (em cima, à direita), escolher BikeShop (todos) e carregar em ▶. Arranca o registo e os outros 5, cada um no seu separador da janela Run.

    Para correr só um, as configurações estão na pasta BikeShop da mesma lista. O bikeshop-registo tem de estar sempre a correr.

  6. Confirmar

    Esperar uns 30 segundos, para os serviços se registarem no Eureka, e no terminal:

    .\scripts\e2e-test.ps1
    Todas as verificacoes OK

  7. Parar

    Botão ■ na janela Run (Ctrl+F2) para os serviços; depois a infraestrutura:

    docker compose down

Kubernetes (Minikube)

Porquê? O slide 06 pede o projeto todo no Kubernetes, com réplicas, ConfigMap e Secret, e uma nova versão posta em produção. É opcional: para usar a loja ou programar, basta Docker, VS Code ou IntelliJ. Aqui os 6 serviços correm no cluster (perfil bikeshop-minikube, namespace bikeshop), o catálogo com 2 réplicas; a infraestrutura continua no Docker.

  1. Abrir o Docker Desktop e o terminal

    Esperar por Engine running, abrir >_ Terminal e ir para a pasta do projeto. Precisa também do Minikube e do kubectl instalados.

    cd C:\ESTG\BikeShop

  2. Pôr no cluster

    Arranca o Minikube se preciso, compila, constrói as imagens, carrega-as no cluster e aplica k8s/. Na primeira vez demora alguns minutos.

    powershell -ExecutionPolicy Bypass -File scripts\k8s-deploy.ps1
    deployment "bikeshop-encomendas" successfully rolled out

  3. Abrir a gateway do cluster

    Deixar este comando a correr; a interface fica em http://localhost:19080/.

    kubectl port-forward -n bikeshop svc/bikeshop-gateway 19080:80

  4. Testar e ver os pods

    Noutro terminal, também na pasta do projeto:

    powershell -ExecutionPolicy Bypass -File scripts\e2e-test.ps1 -Gateway http://localhost:19080
kubectl get pods -n bikeshop

  5. Nova versão a partir do Docker Hub

    Muda um serviço para uma imagem publicada e acompanha a troca dos pods, um de cada vez.

    powershell -ExecutionPolicy Bypass -File scripts\k8s-atualizar.ps1 -Utilizador 8220800 -Servico catalogo -Versao 2.0

  6. Parar o cluster

    Os pods voltam no próximo minikube start.

    minikube -p bikeshop-minikube stop
